# 폭염·호우 피해의 모양을 읽는 취약 상권 조기 경보

**2026 빅콘테스트 AI데이터 분석 분야 · Team PICKBACK**

서울 강남구·강원 춘천시의 2025년 7~12월 신한카드 결제 데이터와 기상청 기상·특보 데이터로, 폭염·호우 때 **어떤 업종이 반복해서 평소보다 크게 줄었는지**, 그 피해가 **얼마나 깊고(Impact) 오래 쌓였고(Cumulative) 늦게 회복됐는지(Recovery)**, 그리고 **언제·어떻게·누가 줄었는지**를 분석했습니다. 날씨로 매출 변화를 예측하는 모델을 더해, 예보만으로 피해가 클 업종을 미리 고를 수 있게 했습니다.

> 핵심 메시지: 폭염·호우 피해는 업종마다 모양이 다르다. 언제·어떻게 줄었는지에 맞춰 지원해야 하고, 예보로 미리 고를 수 있다.

## 주요 결과

| 항목 | 결과 |
|---|---|
| 분석 단위 | 152개 지역×업종 (강남 83, 춘천 69) × 4개 시간대 × 184일 |
| 특보 이벤트 | 폭염 4번(두 지역 같음), 호우 강남 5번·춘천 6번 |
| 취약 후보 | **43개** — 강남 폭염 17, 강남 호우 3, 춘천 폭염 14, 춘천 호우 9. 세탁소는 네 조건 모두에서 후보 |
| 언제 | 폭염은 낮 집중·하루 전체 감소, 호우는 대부분 하루 전체 감소(춘천 호우 9개 중 8개) |
| 어떻게 | 방문 감소 19 · 혼합 11 · 지출 감소 13 (여름 객단가 기준 보조 결과: 32 · 8 · 3) |
| 누가 | 43개 중 39개는 특정 고객층(외지인/거주민) 쏠림 없음 |
| 예측 모델 | 기상 모델이 과거 평균 예측보다 업종 피해 순위를 더 잘 맞힘 (4개 조건 중 3개). 가장 깊은 감소(Impact) 순위상관 0.32~0.57 vs 0.19~0.24 |

## 분석 흐름

```
① 평소 매출 B 추정 (baseline V4, 날씨 변수 없이 평시 날만 학습)
        ↓
② y = (실제 S − 평소 B) ÷ 그날 평소 매출 합
        ↓
③ 2단계 모델: 날씨로 y 예측 (LightGBM Huber)
        ↓
④ 취약 판정·3축 계산 ── 실제 y와 예측 y에 같은 공식 적용
   · 평시 날 1,000번 추출로 만든 범위보다 낮으면 '감소'
   · 이벤트 절반 이상·최소 2번 감소 → 취약 후보
   · Impact / Cumulative / Recovery 백분위 평균으로 순위
        ↓
⑤ 유형 분류: 피해 모양 · 시간대 유형 · 업종 성격 · 방문/지출 · 외지인/거주민
        ↓
⑥ 대응 유형 6개 + 특보 전·중·후 운영
```

판정 기준(평시 범위, 반복 조건, 유형 기준값, 모델 비교 규칙)은 **결과를 보기 전에 정했고**, 바꾼 경우에는 원래 결과를 주 결과로 두고 보조 결과로 함께 제시했습니다.

### 1. 데이터 준비 (저장소에는 없음)

대회 데이터라 저장소에 올리지 않았습니다. Google Drive에 아래처럼 두면 노트북이 파일 이름으로 자동으로 찾습니다.

├─ outputs/    ← 01 결과 (자동 생성)

### 2. Colab에서 실행

1. `reproduce/` 노트북 4개를 Drive `big_contest` 아래에 올립니다.
2. **01은 런타임 → 런타임 유형 변경 → T4 GPU**로 바꾼 뒤 실행합니다(아래 '재현 환경' 참고).
3. 01 → 02 → 03 → 04 순서로 각 노트북을 위에서부터 실행합니다. 03과 04는 서로 독립이라 02 다음에 어느 쪽을 먼저 돌려도 됩니다.
4. 발표·부록 그래프가 필요하면 `figures/` 노트북을 실행합니다. Drive에 재현 노트북(또는 `재현코드.zip`)이 있으면 02~04를 자동으로 불러 씁니다.

각 노트북 첫 셀이 Drive 연결과 패키지 설치를 합니다. 로컬에서 돌릴 때는 `pip install -r requirements.txt` 후 각 노트북 첫 셀의 경로(`ROOT`, 01은 `DATA_DIR`·`OUT_DIR`)만 바꾸세요.

### 3. 재현 확인

| 단계 | 이 값이 나오면 재현된 것 |

| 01 | 152개 지역×업종(강남 83, 춘천 69), 평시 금액가중 y 약 +2.0% |
| 02 | 취약 후보 강남 폭염 17·호우 3, 춘천 폭염 14·호우 9 (합계 43) |
| 03 | 업종 순위상관(모델/과거 평균) 강남 폭염 0.42/0.39, 강남 호우 0.34/0.27, 춘천 폭염 0.40/0.38, 춘천 호우 0.35/0.27 |
| 04 | 방문/지출/혼합 강남 폭염 5/8/4, 춘천 폭염 7/5/2, 강남 호우 1/0/2, 춘천 호우 6/0/3 |

### 재현 환경

- 무작위 추출(평시 범위, 모델 학습)은 모두 시드를 고정했습니다.
- **baseline(01)은 Colab T4 GPU + xgboost 3.4.1**로 만들었습니다. 같은 조건에서는 두 번 돌려도 B가 칸 하나까지 같습니다.
- CPU로 학습하면 subsample(0.8)의 행 추출 방식이 달라 B가 칸 단위로 −9%~+10% 달라지고, 취약 후보가 43개 대신 47개가 됩니다. 43개 중 42개는 그대로이고, 바뀐 6개는 반복 기준 경계에 있는 업종입니다. `reproduce/baseline_GPU_CPU비교.ipynb`로 확인할 수 있습니다.

## 방법 요약

| 단계 | 핵심 설정 |
|---|---|
| 전처리 | 법인(행 5.9%, 금액 15.9%)·세금공과금·ZZ_나머지 제외 → 날짜×지역×업종×6시간 집계 → 매출 있는 날 80% 미만 칸 제외. 한파·대설 특보일 제외 |
| baseline V4 | XGBoost Tweedie(1.5), 평시 날만 학습(특보 없음 & 일강수 < 10mm), ISO 주차 5묶음 교차 적합(±3일 제외), 변수 22개(달력·변동성, 날씨 없음), 사후 보정 없음 |
| 이벤트 | 특보(주의보 이상)가 이어진 기간마다 하나. 연휴 블록 ±1일(8/14~18, 10/2~10, 12/24~26)은 특수일로 2단계 분석에서 제외 |
| 취약 판정 | 같은 날짜 수·요일 구성의 평시 날 1,000번 추출 → 기간 차이율 5~95% 범위보다 낮으면 감소. 이벤트 절반 이상·최소 2번 감소면 취약 후보. 보험·통신요금(정기 청구)·결제대행(가맹점 식별 불가)은 순위에서 보류 |
| 3축 | Impact = 하루 변화율 3일 평균 최솟값 / Cumulative = Σ(실제−평소) ÷ 평균 하루 평소 매출 / Recovery = 종료 후 회복 기준에 2일 연속 들어온 날까지(끊기면 "○일 이상") |
| 2단계 모델 | LightGBM Huber(α=0.1), 변수 14개(시간대·일 기온·강수·습도·풍속, 전3일강수, 폭염연속일수, 특보 등급 등). 이벤트 묶음을 통째로 빼고 학습해 검증 |
| 모델 비교 | 과거 평균 예측(같은 업종·시간대·특보 종류의 과거 y 평균), 평소대로(y=0)와 비교. 사전 규칙: 이벤트별 업종 순위상관 평균이 높고 이긴 이벤트가 절반 이상이면 "모델이 더 잘 맞힘" |
| 감소 분해 | 매출 = 건수 × 객단가로 나눠 건수 몫 ≥70% 방문 감소, ≤30% 지출 감소. 외지인 = 가맹점과 다른 시·도 거주 고객 |

판정 장치 점검: 특보가 없던 기간에 같은 판정을 하면 폭염 길이에서 19.9%, 호우 길이에서 9.4%가 '감소'로 나와(기대 5%), 사전 규칙에 따라 7일 묶음 추출 보조 결과(12.1%, 6.2%)를 함께 제시했습니다.

## 주의

- 결과 파일과 노트북 출력에는 업종별 실제 매출이 들어 있습니다. 대회 데이터 공개 규정에 따라 **저장소에는 출력을 지운 노트북만** 올립니다.
- 강남은 '거주민'이 서울 시민 전체라 강남의 외지인/거주민 결과는 참고용입니다.
- 피해 모양(상대적 심각·급락·지속 침체·상대적 완만)은 같은 지역·기상의 후보끼리 비교한 상대 구분입니다.
- 결과는 반복 감소를 관찰한 것이며, 날씨만의 인과 효과로 단정하지 않습니다.
