# 재현 코드 (reproduce)

팀 분석을 처음부터 다시 만드는 노트북 4개입니다. 저장소 전체 설명은 [상위 README](../README.md)를 보세요. 원본 데이터만 Drive에 두고 **01 → 02 → 03 → 04 순서로** 위에서부터 실행하면 됩니다. 각 노트북은 앞 노트북의 결과 파일을 파일 이름으로 자동으로 찾아 읽습니다.

## 노트북별 핵심 설정

**01 baseline V4**
- XGBoost Tweedie(1.5), 평균 예측, 목표값 = 매출/1만 원
- 학습: 평시 날만(폭염·호우 특보 없음 & 일강수 10mm 미만), 한파·대설 날 제외
- 교차 적합: ISO 주차 % 5, 예측 주 ±3일 학습 제외
- 변수 22개: 범주 3, 기본 달력 3, 달력 8, 변동성 4(묶음마다 학습 평시 행으로만 계산), 주기 달력 4(유치원 2곳만)
- 공휴일 → 일요일 처리: 강남 전 업종 + 춘천 11개 업종
- 전처리: 법인·세금공과금·ZZ_나머지 제외, 매출이 있는 날 80% 미만 칸 제외, 휴무 칸 표시

**02 취약 판정·유형**
- 이벤트: 특보(주의보 이상)가 이어진 기간마다 하나 (`GAP_MERGE = 0`)
- 특수일(2단계): 연휴 블록 ±1일 8/14~18, 10/2~10, 12/24~26 — 판정·3축에서 결측
- 평시 범위: 같은 날짜 수·요일 구성의 평시 날 1,000번 추출, 기간 차이율의 5~95%
- 취약 후보: 이벤트 절반 이상·최소 2번 감소. 보험·통신요금·결제대행은 순위에서 보류
- 3축: Impact(3일 평균 최솟값), Cumulative(Σ차액 ÷ 평균 하루 B), Recovery(2일 연속 회복 기준 진입까지 일수, 끊기면 "○일 이상")
- 순위: 후보끼리 축별 백분위 평균
- 유형 기준(실행 전에 정함): 피해 모양 0.5 분할, 시간대 유형(30%·50%·1.5배·5%), 회복 지연 3일. 보조 표시: 경계 사례, −5% 기준 판정, 금액 기준 시간 이동, 보고서용 시간대 묶음

**03 2단계 모델**
- LightGBM Huber(α=0.1), 트리 400, 학습률 0.03, 잎 31, 잎당 최소 200행, 샘플링 0.8, L2 1.0
- 변수 14개: 지역·업종·시간대 / 시간대 최고기온·강수·강수시간·습도·풍속 / 일 최고기온·일 강수 / 전3일강수·폭염연속일수 / 폭염·호우 등급
- 검증: 이벤트 묶음 통째로 제외(±3일)
- 사전 판단 규칙: 이벤트별 업종 순위상관 평균이 과거 평균보다 높고 이긴 이벤트가 절반 이상이면 "모델이 더 잘 맞힘"

**04 감소 분해**
- 방문/지출: 건수 몫 ≥70% 방문 감소형, ≤30% 지출 감소형, 그 사이 혼합형. 업종의 시간대 유형에 맞는 시간대로 봄
- 보조: 평소 객단가를 여름 평시 날(8월·9월 상순)로 계산
- 외지인 = 가맹점과 다른 시·도 거주(거주지 '정보없음' 제외). 이벤트 외지인 비중이 평시 범위 밖인 이벤트가 절반 이상·최소 2번이면 외지인/거주민 주도

## 재현 확인용 숫자 (팀 실행 결과)

같은 원본 파일로 돌렸을 때 아래와 같으면 재현된 것입니다. 무작위 추출은 모두 시드를 고정해서 매번 같습니다.

**01은 반드시 GPU로 돌리세요.** 팀 결과의 B는 Colab T4 GPU + xgboost 3.4.1로 만들었고, 같은 조건에서는 B가 칸 하나까지 똑같이 나옵니다(두 번 돌려 확인). CPU로 돌리면 모델이 행을 뽑는 방식(subsample 0.8)이 달라 B가 칸 단위로 −9%~+10% 달라지고, 02의 취약 후보도 43개가 아니라 47개가 나옵니다(42개는 같고, 바뀐 6개는 반복 기준 경계 업종). `baseline_GPU_CPU비교.ipynb`로 직접 확인할 수 있습니다.
